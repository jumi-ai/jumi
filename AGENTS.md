# AGENTS.md

OpenCode and Claude Code load this file for sessions in this checkout, including Jumi's own implement and review runs. It is facts about this repository, not a second README. `README.md` is the human overview. `deploy/contract.md` is the GitOps runtime contract.

## Keep this file current

If a change makes any command, path, pin, or rule in this file wrong, update `AGENTS.md` in that same change. Do not leave it for a follow-up. Do not add a `CLAUDE.md` that disagrees with this file. OpenCode uses `AGENTS.md` and ignores `CLAUDE.md` when both exist.

Reviewers: a stale line is a finding. Do not edit this file during review.

## Layout

Application code is `scripts/opencode` (TypeScript on Bun). Tests are `scripts/opencode/test`. Tool pins are `.gitea/tool-versions.env`. There is no Helm chart and no Compose file here. Cluster GitOps lives in another repository. Do not copy another deploy's hostnames, owner names, or secrets into this tree.

The worker image ships Temurin 21 (`JAVA_HOME=/opt/java/openjdk`). The reviewer image has no JVM. Do not add one. `type: agy` is refused unless `FORGE=github`.

## Verify

From `scripts/opencode`, after `bun install --frozen-lockfile`:

- `bun run ci` runs `biome check`, `tsc --noEmit`, and `bun test`. That is the `checks` job. It does not start Postgres.
- `bun run test:pg` is the queue and lease suite. It needs `JUMI_TEST_DATABASE_URL`. CI runs it only in `postgres-queue`. Do not treat `bun run ci` as proof that job passed.

Biome is 2-space indent, double quotes, semicolons, line width 120. Do not reformat unrelated files.

Dockerfile or `.gitea/tool-versions.env` bumps are proved by the image jobs, not by `bun run ci`.

A new or removed required env key, required constraint, UID, probe, command, port, or image target is a major bump of `deploy/contract.md`. A new optional env key is a minor bump. Do not invent ciphertext.

## Implement

Read the parent-injected `JUMI_*.md` files. Do not inventory the repo first. Do not call the forge API or `tea`. Do not ask questions. Do not force-push. Do not open the pull request.

You may commit and push the task branch. Do not commit `JUMI_PR.md`, `JUMI_SKIP.md`, `JUMI_BLOCKED.md`, or `JUMI_TASK.md`. When finished, write `JUMI_PR.md` at the repo root: what changed, why, and what you ran to verify. If there is nothing to change, write `JUMI_SKIP.md` with a short reason and do not commit it.

Verify once at the end. For a TypeScript change, that is `bun run ci` in `scripts/opencode`. Run `bun run test:pg` only if you touched queue or lease SQL and Postgres is available.

Conflict jobs resolve only the paths listed in `JUMI_CONFLICT.md`. One adjacent file only if the resolution needs it. Do not rebase.
